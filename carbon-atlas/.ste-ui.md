# Portal UI text

This file holds the visible text of the portal, for the ASD-STE100 checker. `portal/index.html`
and `portal/app.js` own these strings, and this file is a copy of them. Change a string in the
page, change it here, and run the checker again.

It ships with the repository, because the style rule is part of the method, and a reader must be
able to run the check. It documents nothing about the program. `portal/README.md`, `REFERENCE.md`
and `ARCHITECTURE.md` do that.

Last synchronised with the portal on 2026-09-23. This copy holds the strings of the Source
discrepancy tab, the coverage view of the Raw data tab, and the data-quality flag of a country.
A string that the page builds from `data/pairs.json`, such as the `method` text of the
measurement, is not here. `atlas/analyse.py` owns that text, and not the page.

Read `portal/index.html` and `portal/app.js` again before you trust a checker run of a later
date. This file is a copy, and a copy goes stale.

A string that the page builds from a data file is not here. The `method` text of the measurement
comes from `data/pairs.json`, and the note of the coverage panel comes from `data/health.json`.
`atlas/analyse.py` and `atlas/export.py` own that text, and not the page.

The horizon comes from the returned curve. The portal reads it for each country.

Why a score is not on this page yet.

A score needs the same hour from two sides: the forecast that a publisher made before the hour,
and the measurement of that hour. The store holds a small number of captured runs, from a small
number of days. A mean error here describes those days and not the publisher.

The mean error and the bias need many runs at each lead time. That needs some weeks of capture.

The skill against persistence divides the error of the forecast by the error of a simple rule. The
rule is that the next hour is the same as this hour. A ratio above 1 means that the forecast is
worse than no forecast.

The decision test is the test that matters for a scheduler. Did the forecast pick the cleanest
hour, and what did a wrong choice cost in gCO2eq/kWh?

Two sources in the register keep their own forecast history. A score of those two is possible on
the first day of collection.

How a value reaches this page.

The publisher, at the published rate limit.

The payload. It is written to disk and hashed, before anything reads it. The evidence of every
number stays on disk.

Four guards. The field set, the value range, the time step and the count. A payload that fails a
guard writes no record.

The store. A new row for each value. An equal value writes nothing, and a changed value writes a
new revision. No row is ever overwritten.

This page. The store writes the data files that this page reads. The page makes no request to a
publisher.

The coverage table above is the record of what the store asked for and what it received. A day
with no ok row is asked for again, so a gap closes by itself on the next day. An empty day is an
